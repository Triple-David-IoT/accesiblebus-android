# TM01 – MQTT Broker Configuration and Connection Test

## Overview

This document records the validation of the TM01 test for the AccesibleBusApp project. The goal was to verify that the application can connect to an MQTT broker configured by the user, persist that configuration, and attempt to reconnect after the application is restarted.

## Test Environment

- **Android application:** AccesibleBusApp
- **Android device:** Physical Android device
- **MQTT broker:** Eclipse Mosquitto `2.1.2-alpine`
- **Broker deployment:** Docker container
- **Container name:** `mosquitto_service`
- **Container ID at the time of the test:** `dab7ac87eafd`
- **Published port:** TCP `1883`
- **Docker port mapping:** `0.0.0.0:1883->1883/tcp` (also published on IPv6)
- **Connection profile:** Laboratory

The phone and the computer hosting Docker were connected to the same local network. The app used the computer's local IPv4 address as the MQTT host and port `1883`.

> The local IP address is intentionally not recorded because it depends on the network and may change.

## Test Procedure

1. Started the Mosquitto Docker container and confirmed that it was running.
2. Retrieved the computer's local IPv4 address using `ipconfig`.
3. Opened AccesibleBusApp on the physical Android device.
4. Selected the **Laboratory** profile.
5. Entered the computer's local IPv4 address in **MQTT Host** and set **MQTT Port** to `1883`.
6. Saved the preferences.
7. Checked Android Studio Logcat for the MQTT connection result.
8. Changed the MQTT host to an intentionally incorrect local IP address.
9. Saved the configuration, closed the app completely, and launched it again.
10. Selected the Laboratory profile and checked that the saved host remained in Preferences.
11. Observed that the app repeatedly attempted to connect using the incorrect saved address.
12. Restored the correct computer IP address and saved the configuration. The connection worked again.

## Results

| Verification | Result | Notes |
|---|---|---|
| Mosquitto container running | **PASS** | Docker reported the `mosquitto_service` container as running. |
| Broker port published | **PASS** | TCP port `1883` was published from the container to the host. |
| Connection from physical Android device | **PASS** | The app connected when configured with the computer's reachable local IP address. |
| MQTT host and port configurable in the app | **PASS** | The broker host and port were set through Preferences. |
| Configuration persisted after app restart | **PASS** | The intentionally incorrect host remained saved after closing and reopening the app. |
| App used the saved configuration on startup/profile selection | **PASS** | The app attempted to connect using the saved host. |
| Automatic retry behavior with an unreachable host | **OBSERVED** | The app continued attempting to connect while the configured host was incorrect. |
| Recovery after restoring the correct host | **PASS** | The app connected again after the correct address was restored. |

## Conclusion

**TM01 was successfully validated.**

The test confirmed that AccesibleBusApp can connect to a Mosquitto broker running in Docker from a physical Android device, save the MQTT connection settings, retain them across an application restart, and use the saved settings when attempting to connect.

When an unreachable host was configured, the application repeatedly attempted to connect. After the correct host was restored, the connection succeeded again.

## Notes

- For a physical Android device, use the computer's reachable local network IP address as the MQTT host. Do not use `localhost`, because that refers to the phone itself.
- The broker must be reachable from the phone over the local network.
- The test used the unencrypted MQTT TCP port `1883` on the local network.
- Repeated connection attempts were observed during this test; this document does not establish a specific retry interval.
