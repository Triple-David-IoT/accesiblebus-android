# TM02: stops from the CRTM, and the local copy without network

Pixel 8 emulator, default debug build (sample API; the stops always come from the CRTM).

## With network (`01-online.png`)

The app downloads the four stops with the A01 query, straight from the CRTM ArcGIS service
over HTTPS. This was the open point of `docs/datos.md`: the download works from the device.
The list follows the manifest order (456, 459, 460, 461), not the response order
(459, 460, 461, 456), and shows the CRTM name and code of each stop.

The copy saved in the app files keeps the date and the source:

```json
{"fetchedAt":"2026-11-08T12:23:13Z","source":"https://services5.arcgis.com/UxADft6QPcvFyDU1/arcgis/rest/services/M6_Red/FeatureServer/0/query?where=CODIGOESTACION%20IN%20%28%27456%27%2C%27459%27%2C%27460%27%2C%27461%27%29&outFields=CODIGOESTACION%2CDENOMINACION&outSR=4326&f=geojson","stops":[{"sequence":1,"code":"456","name":"Pº PRADO-BANCO DE ESPAÑA","latitude":40.4180667883511,"longitude":-3.6...
```

## Airplane mode, with a copy (`02-airplane-cache.png`)

"Actualizar" fails to reach the CRTM and the list stays, labelled
"Copia local del 08/11/2026 12:23: sin conexión con el CRTM" (the emulator clock is UTC).

## Airplane mode, without a copy (`03-airplane-no-cache.png`)

After clearing the app data, the screen says that the stops could not be loaded and that there
is no local copy, with the technical detail below. No stop is made up.

## Unit tests

`StopsRepositoryTest`: the app manifest equals `contracts/manifest.json`; the query has the
A01 parameters; the real answer in `contracts/samples/stops.geojson` is sorted by the manifest
with `[longitude, latitude]` read correctly; the copy is saved and used without network; an
answer with a missing stop is rejected (the saved copy is shown if there is one); a broken
copy is ignored.
