# TM05 — Sensor Context Estimation (C08)

## Test objective

Verify that the C08 sensor context estimator reads the phone's light and proximity sensors, produces a `PhoneContext` result within the configured time window, and releases sensor listeners when the estimation finishes.

The tests were executed on a physical Android device with the application package `dte.masteriot.accessiblebus`.

## Configuration and decision criteria

| Item | Configured / observed value |
|---|---|
| Light sensor | Available (`light_ltr569`) |
| Proximity sensor | Available (`prox_ltr569`) |
| Proximity sensor maximum range | `5.0` |
| Proximity reading for near | `0.0` |
| Proximity reading for far | `5.0` |
| Darkness threshold (`L_osc`) | `5 lux` |
| Bright-light threshold (`L_luz`) | `20 lux` |
| Sensor acquisition timeout | `1500 ms` |

The decision criteria used for the functional checks are:

- `COVERED`: proximity is near (`0`) and light level is below `5 lux`.
- `UNCOVERED`: proximity is far (`5`) or light level is above `20 lux`.
- `UNKNOWN`: available evidence is insufficient or falls into the undecided light interval (`5–20 lux`) without another conclusive condition.
- If a sensor is physically absent, the estimator may use the other available sensor according to the degraded-mode policy.
- If a sensor exists but has not produced a reading before the timeout, this is an insufficient-evidence case and must be handled distinctly from a physically absent sensor.

> **Implementation note:** The timeout policy has been adjusted and verified. A physically available and successfully registered sensor that does not provide a fresh reading within `1500 ms` is treated as insufficient evidence; the estimator returns `UNKNOWN`. This is distinct from a physically absent sensor, for which the other available sensor may be used according to the degraded-mode policy.

## Test environment and execution

The test was run as an Android instrumented test from `androidTest`, invoking `ContextEstimator.estimate()` directly. Logcat tags used for evidence were `C08` and `C08_TEST`.

The test captures:
- sensor availability;
- raw light and proximity readings;
- the selected context;
- timeout behavior;
- active-listener count after the estimation finishes.

**Observed values:**

|---|---:|

### TM05-C08-F05 — Listener cleanup after estimation

**Setup:** Verify listener cleanup after successful acquisition and after the timeout path.

**Expected:** No sensor listeners remain registered after `estimate()` completes.

**Result:** PASS. The instrumentation test reported `0` active listeners after release and at the end of estimation for the executed scenarios.

## Listener cleanup verification

For each observed execution, the logs reported:

```text
Listeners activos tras liberar: 0
Listeners activos al finalizar: 0
```

This confirms that no listeners remained active after the tested estimation completed, including the run that reached the `1500 ms` timeout.

The recorded evidence covers successful sensor acquisition, timeout with partial evidence, and listener cleanup after both successful and timeout completion. The physically-missing-sensor branch and cancellation cleanup were not simulated in these device runs; they should be treated as additional test cases if required by the complete acceptance criteria.
