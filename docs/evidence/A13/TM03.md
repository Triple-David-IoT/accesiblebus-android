# TM03: a command sent while the API is down runs once

Pixel 8 emulator (Android 17) with the debug build pointing at the laboratory API:

```bash
./gradlew installDebug -PuseSampleApi=false -PapiBaseUrl=http://192.168.1.172:8000/
```

## Steps and results

1. Profile, Passenger: the stop list comes from the real `/sync` (`01-stops.png`).
2. Stop 459 opens Confirm (`02-confirm.png`).
3. `docker stop api_service` on the VM, then "Solicitar asistencia". The app shows
   "Pendiente de envío" with the network error and a retry button (`03-api-down.png`).
   The key is in the app preferences before any answer:

   ```xml
   <string name="create:28a11785-b22e-45ff-b429-4751b89c1119">72eab27a-5fcf-46f2-8794-a720c8e7800d</string>
   ```

4. A second try with the API still down failed again and kept the same key.
5. `docker start api_service`, then "Reintentar". The app opens Tracking with the new request,
   PENDING (`04-retry-tracking.png`), and the preferences no longer hold the key.
6. In the database:

   ```text
   requests on that visit: 1
   commands with that key: 1 (create_request)
   ```

## Conflict

With the request still at version 1 in the app, the driver accepted it with curl (version 2).
"Cancelar solicitud" from the app got `409 VERSION_CONFLICT` with the current request; the app
applied it, shows "Aceptada por el conductor" and explains that the request changed
(`05-version-conflict.png`). A new attempt uses a new key, built from version 2.

## Unit tests

`AssistanceRepositoryTest` covers the same rules without a network: API down then retry with
the same key, a lost answer recovered with the same key, a conflict that applies the current
resource, keys left by a previous run, trip commands, and the merge rules (higher version,
received stays true, ENDED never reverts, another trip replaces the snapshot).
