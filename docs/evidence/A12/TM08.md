# TM08: stop detail and Confirm, in both orientations

Pixel 8 emulator, debug build pointing at the laboratory API
(`-PuseSampleApi=false -PapiBaseUrl=http://192.168.1.172:8000/`), font scale 1.0.

## Screens

- **Detail** (`01-detail.png`): CRTM name and code, the EMT number shown on the stop sign,
  the line, and the visit in the laboratory trip ("parada 3 de 4"). "Pedir asistencia aquí"
  opens Confirm.
- **Confirm, portrait** (`02-confirm-portrait.png`): stop, codes, trip, type of assistance and
  "Solicitar asistencia" in one column.
- **Confirm, landscape** (`03-confirm-landscape.png`): two panels, details on the left and the
  action on the right. Everything fits without scrolling and inside the system bars and the
  camera cutout. The layout is chosen with `LocalConfiguration.current.orientation`; the
  font size is not reduced.
- **Stop already passed** (`06-detail-passed.png`): the button is disabled and the screen says
  that the bus already passed. The API has no `advance` yet (B05), so for this check the trip
  was moved in the laboratory database (`last_passed_sequence = 1`), as the A07 tests do.

## Turning the phone while the command is on its way

1. In landscape, `docker pause api_service`: the API accepts the connection and does not answer.
2. "Solicitar asistencia" at 13:37:51, and the phone turned to portrait at 13:37:52.
3. After the rotation Confirm still shows "Pendiente de envío…" with the button disabled
   (`04-sending-rotated.png`): the command lives in the ViewModel, which survives the
   rotation, and its key was saved before sending.
4. `docker unpause api_service`: the answer arrives and Tracking opens once (`05-tracking.png`).
5. In the database:

   ```text
   requests at stop 460: 1
   create_request commands since the reset: 1
   ```

The plan places the key in the ViewModel; here the repository generates and saves it before the
call (A13), which gives the same guarantee for every command, not only for Confirm.
