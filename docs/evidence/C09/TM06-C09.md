# TM06 — Decision announcements, voice and accessibility

## Scenario

Verify that passenger decision announcements follow the accessibility preferences and phone context, that speech is handled safely across app/device lifecycle changes, and that already announced decisions are not replayed after an app restart.

This evidence covers **C09 — Announcement Coordinator and Voice**.

## Code version

- Branch: `c/c09-announcements` (proposed; confirm the actual branch name before merging).
- Commit: Not recorded.
- Build/version: Not recorded.

## Configuration

- Android application running on physical mobile devices.
- Backend API and MQTT broker: real project services, running in the same setup used for the tests.
- Voice preferences tested: `AUTO`, `ALWAYS` and `OFF`.
- Context detection uses the device's light and proximity sensors.
- Screenshots and Logcat output were not captured during testing.

## Steps

1. Run the passenger application on a physical device connected to the project backend and MQTT broker.
2. Set the voice preference to `AUTO`. Test with the phone covered and uncovered.
3. Set the preference to `ALWAYS` and verify that the decision is spoken.
4. Set the preference to `OFF` and verify that no voice announcement is played.
5. Verify that vibration and on-screen announcements behave according to the selected mode and configuration.
6. Enable TalkBack and verify that announcements do not overlap or block the announcement queue.
7. Start a voice announcement and lock the device while it is speaking. Unlock the device and verify that the interrupted announcement does not start again.
8. Receive a decision, force-stop the application, and reopen it. Synchronize again and verify that the previously announced decision is not replayed.
9. Synchronize without changing the decision and verify that it remains deduplicated. Receive a new decision/version and verify that it can be announced.

## Result

**Passed in the manual tests reported by the developer.**

- `AUTO`: covered and uncovered contexts are detected and produce the expected announcement behavior.
- `ALWAYS`: voice announcements work.
- `OFF`: voice announcements are disabled.
- Vibration and on-screen feedback work.
- TalkBack works without blocking the queue or causing overlapping announcements.
- Locking the device interrupts the current TTS playback; unlocking does not replay that interrupted announcement.
- After force-stopping and reopening the app, decisions already recorded as announced are not replayed.

No screenshots, captured Logcat output, or measured sensor values are available for this run. The results above record the manual tests performed; no visual or log evidence is claimed.

## Notes and limitations

- The announcement deduplication key is `requestId + version` and is persisted using `PreferencesAnnouncedDecisions`.
- The key is recorded before the announcement is submitted to the coordinator. A force-stop in the small interval between persistence and submission could therefore result in an announcement being missed. This edge case was not tested.
- This is a retrospective record of the tests performed, not a substitute for screenshots or saved device logs.
